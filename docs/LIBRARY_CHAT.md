# 文献库对话（2.0.0 第一版）

入口：Zotero 工具 → SI → 科研工作台 → **文献库对话**。

## 日常使用

1. 选择个人图书馆或一个群组库。各图书馆的资料和索引独立处理。
2. 选择整个图书馆、指定分类（可包含子分类）或当前选中文献。选中文献模式通过“重新读取文献库选择”刷新；附件会归并到父文献。
3. 可用年份、标签和 SI 高亮类别进一步筛选。
4. 默认使用元数据、摘要、高亮、批注与用户笔记。AI 笔记默认关闭。
5. 输入问题后点击“发送问题”；点击答案中的 `[S1]` 或折叠来源列表可定位文献、笔记或 PDF 注释。
6. 每条完整回答可保存为独立 Zotero 笔记。分类模式会将笔记加入该分类；群组库需要写权限。保存不会覆盖已有文献笔记。

### 三种操作

- **发送问题**：中文分词、英文词项和字段加权的本地检索，去除重复文本，每篇最多选 4 段、合计最多 30 段，资料上下文目标不超过 14,000 字符。不会宣称覆盖全库。支持结合前两轮问题及涉及文献标题理解追问；更换范围后重置追问上下文。
- **范围综述**：不做 Top-K 截取，按约 14,000 字符一批处理全部所选资料，再分层整合。目标可留空；显示批次进度。长文笔记/摘要会切片，避免仅总结开头。缓存最近 100 个完成批次；相同资料、目标、模型与配置槽在本次 Zotero 会话中可复用。
- **本地检索 / 统计**：不调用模型，直接统计当前筛选范围；输入关键词时按词项匹配条目，提供年份分布。来源列表最多展示前 100 段，但计数覆盖全部匹配条目。

普通问答是关键词检索，不是跨语言语义搜索。中文提问找不到英文文献时，可补充英文关键词，或使用范围综述。

## 资料边界

索引内容：标题、作者、年份、期刊、DOI、标签、分类、已有摘要、Zotero 笔记，以及已收录的注释原文/评论/颜色/页码。

- **不调用 PDF 正文提取、全文索引、MinerU 或 OCR，不下载 PDF。** 只有用户点击注释来源时才打开相应附件。
- 支持常规文献、独立笔记以及独立 PDF 的书目和注释记录；同一条目在多个分类中不重复计数。不同 Zotero 条目仍独立处理，不自动按 DOI 合并。
- 注释可在 PDF 不在本地时参与分析；点击时会回退定位文献。
- 图片和手绘注释不识别图像内容，但其已有文字批注可参与分析。
- 外部 PDF 内尚未导入 Zotero 的注释不可用。
- SI 自动高亮按约定颜色识别五类；普通手动高亮不擅自推断类别。选定 SI 类别时仅使用该类注释和批注。
- 元数据仅支持书目信息；无摘要、笔记或注释时，不能推断实验发现。
- AI 笔记通过 `SI AI` 标签或 SI 已知标题前缀识别；其他工具创建的 AI 笔记可手动加 `SI AI` 标签排除。SI 自动批注作为“AI 高亮分类”单独标注。

## 来源与保存

每段资料保留图书馆、父条目、笔记/注释的 ID 与 key。来源列表展示的是输入资料；答案中的来源编号表示模型引用。不存在的编号替换为“来源未核实”，但这不等同于自动验证每个论断的正确性。

保存的笔记包含问题、范围、回答、时间和来源摘录；来源链接采用 Zotero 本地链接。新笔记附有 `SI AI` 标签，默认不进入后续问答证据。

对话显示每次耗时和接口返回的 Token 用量，继续计入原有 Token 面板。缓存复用部分不重复计费。未返回用量以及中断请求的实际计费无法精确统计，会明确提示。

## 索引与生命周期

- 首次点击索引或发起任务时建立本地索引。每次提问前检查记录变化；不变的条目复用已解析的笔记/注释资料。
- 使用 Zotero 数据 API 和变更通知；根据子条目修改信息、分类变化和删除情况更新。缓存损坏可从 Zotero 重建。
- 缓存文件：Zotero 数据目录下 `si-library-index-<libraryID>.json`，为本地资料的明文副本，使用 Zotero 的原子写入接口；不修改 Zotero 数据库结构。
- “停止”会取消当前模型 HTTP 请求，并阻止后续批次；已完成批次留在内存。关闭对话窗口也会停止当前任务。
- 对话仅在窗口内保留。服务端保留最近 50 个完整回答供定位和保存，较旧回答应及时保存为笔记。重启 Zotero 后批次缓存和未保存对话不保留，本地资料索引保留。
- 索引在本地进行。远程模型接收本次所需资料；范围综述逐批发送全部所选资料。资料类型开关控制发送内容，索引仍整理完整支持字段。

## 2.0.3：分类核对与总结耗时

分类范围改为通过 Zotero 原生 `getDescendents(false, 'collection', false)` 和 `getChildItems(true, false)` 获取实时成员。支持多层子分类，按条目 ID 去重；不再依赖本地缓存中的分类归属筛选。范围明细展示各分类的总条目、已索引和筛选后数量。本轮问答另显示关键词匹配数量，区分“未索引”和“已索引但未被检索采用”。

文献总结/表格总结新增有上限的会话正文缓存（最多 8 个结果、总计 600 万字符）。按附件、文件路径、修改时间、大小和解析配置区分；文件变化或无法确认文件状态时不复用，失败和空结果不缓存，同一文件的并发提取共享任务。缓存不涉及文献库对话，不读取该功能的 PDF 正文。重启 Zotero 后需重新提取。

完成提示及笔记记录正文准备与模型生成耗时。超过 45,000 字符的论文仍完整分段处理再整合，不截断全文。此优化减少重复提取，无法保证远程 OCR 排队和模型服务的延迟稳定，也不会跳过每次要求重新生成的模型回答。

## 2.0.4：模型等待与 Token 控制

官方 DeepSeek API 的请求设置 `max_tokens: 4096`；`deepseek-flash`、`deepseek-chat`、V4 系列显式使用 `thinking: {type: "disabled"}`。其他提供商不发送 DeepSeek 专用字段，显式选择的 reasoner 模型不强制关闭思考。输出上限不限制输入 Token。

全部模型请求增加单次 180 秒截止时间，覆盖连接和响应读取；超时取消客户端请求，不自动重试。服务端已经发生的用量仍可能计费。收到 `finish_reason: length` 时保留接口用量统计、报告结果不完整，不把截断结果作为成功总结或高亮依据。

高亮最后一条写入后单独显示“正在提交数据库事务（AI 调用已结束）”，避免把总耗时误读为当前保存阶段的耗时。

默认行为依据：https://api-docs.deepseek.com/guides/thinking_mode/ 及 https://api-docs.deepseek.com/api/create-chat-completion/ 。这次没有发起真实模型请求验证，也没有改写用户已安装配置。

## 2.0.5：思考按钮、任务输出上限和部分结果

科研工作台及文献库对话新增“思考：关闭 / 开启”按钮，窗口打开时默认关闭。思考字段仅发送到官方 DeepSeek API 的混合模型；其他提供商和专用 reasoner 模型遵循服务端设置。工作台按任务类型分别保留本窗口的上限选择：文献总结和高亮默认 8192，表格总结默认 16384；文献库默认 8192。可选择 4096、8192、16384、32768 Token，实际支持范围由模型决定。上限作用于每次请求，不能限制输入用量或整个批处理的总用量。

自然语言总结收到 length 结束标记时保留已有正文，标注“未完成”，文献总结和表格总结保存为带同样标记的笔记。批处理单独统计部分结果；历史显示“未完成 · 部分已保存”。文献库回答保留在对话中，可手动保存未完成笔记。分段分析或证据合并触及上限后停止后续请求，不自动续写；未完成批次不进入成功缓存，来源列表仅包含已提交分析的资料。没有正文可保存时仍报错。高亮结构化输出被截断时仍禁止写入批注。

验证覆盖请求参数、默认关闭及开启思考、上限校验、部分结果保存路径、停止后续分段、来源范围及浏览器按钮交互；未调用真实模型服务，未在用户运行中的 Zotero 安装此版本。
